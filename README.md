# GSB Bugfix Task
## 题面
回放资料库接进赛事平台后，数据组和剪辑组互相甩锅：时间轴按整秒取整，拖到 17.6 秒画面停在 17 秒，关键团战总差半拍；收藏点没有有效期，两年前的标记还挂在选手面板上；同一个人反复建收藏，列表滚不到底；别人删得掉我的标记，删完再删还提示成功；热度图只认格子坐标，换一张地图就要重写前端；统计时把界外事件丢掉，边缘交火完全看不到；跨场汇总要人工导表相加；保留策略形同虚设，半年前的录像还在占空间，清理脚本又把本周的比赛一起删了；录像被清理后，收藏点的链接点开直接白屏；新来的剪辑师找不到上周的标记，只能把整场重新剪一遍。replay_heatmap.py 的 ReplayHeatmap 负责定位、收藏、热度统计和保留清理。seek 把目标时间截到片长以内，返回不晚于该时间的最近采样点、截断后的时间、是否正好落在采样点上以及下一个采样点，负数时间、不存在的录像都拒绝。收藏带全库唯一编号、时间、备注、创建者和到期时刻，时间不能超出片长、备注不许留空，每名玩家的收藏总数有上限，重复编号要拒绝；列表只返回未过期的收藏，按时间与编号排序；删除只认创建者，编号不存在也要报错。heatmap 接收命名矩形区域表，按左闭右开统计事件，未落入任何区域的坐标在开启计数时归到 unknown，支持左闭右开的时间窗，不传录像编号时汇总所有未清理的录像，空白区域也要给出零值。prune 按保留时长清掉过期录像和过期收藏，返回被清掉的编号。state 汇总录像、收藏和清理结果，全部与内部数据隔离。

## 运行方式
```bash
python -m pytest tests -q
```
