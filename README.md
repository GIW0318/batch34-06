# GSB Bugfix Task
## 题面
射击玩法加入延迟补偿以后，观战和复盘都开始失真：对手在掩体后探头一枪，服务器按当前帧判定，回放里子弹却穿墙命中；移动靶已经跑出两米，伤害还是记在他头上；弹丸速度很慢的武器按瞬时命中算，飞行时间没人管；回查窗口设得比历史帧保留时间还长，取不到帧直接抛异常把整局打断；历史帧被清理后，旧战报再也无法复算；同一时刻上报两份位置，后一份把前一份覆盖，回放里角色瞬移；校验脚本只看战报里写的命中结果，改一个字段就能骗过；方向向量长度不同导致同一次开火算出两种落点；半径边界上判定忽中忽不中。ballistic_rewind.py 的 BallisticRewind 负责历史帧、开火判定和战报复核。record 按时间登记每个角色的坐标，时间不能倒退，同一时刻再次登记以新坐标整体替换，早于保留窗口的帧被丢弃。fire 用射手给出的原点与方向做射线，方向按单位向量归一化，速度必须为正；先按当前时刻减去延迟定位回查时刻，取不晚于该时刻的最近一帧，没有可用帧时返回未命中并标记历史缺失；把目标在该帧的坐标投影到射线上，投影为负说明目标在身后，垂距超过命中半径算未命中，边界值算命中；命中时飞行时间等于投影距离除以弹速，落点为原点加投影向量。延迟超过配置上限、方向为零、速度非正、目标不在帧里或时间非法都拒绝。validate_replay 接收战报列表，用同一套规则重算命中结果并与战报声明比对，返回是否全部一致、不一致位置和检查条数，字段缺失报错。state 返回帧列表、开火记录和配置的独立副本。

## 运行方式
```bash
python -m pytest tests -q
```
